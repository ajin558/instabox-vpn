# 排障手册

先分清问题在哪一段，再动手。最有用的分界线是服务端日志：
用户测试的时间段里，服务端有没有新记录。

## 1. 服务端日志里完全没有用户那次的记录

说明请求根本没到 Xray，问题在客户端到网关这一段之前，
先不要改服务端配置。

按顺序查：

1. 机器是不是 running，Xray 进程在不在，10000 / 10001 在不在监听，
   两个公开端口是不是还在（`GET /v1/machines/{id}/ports`）。
2. Clash 里代理组选的是不是 PROXY 里的节点，系统代理开了没有，
   模式是规则还是全局。
3. Clash 内核是不是 Mihomo、版本够不够新。原版 Clash 不支持 VLESS，
   旧版 Mihomo 不支持 XHTTP。
4. 浏览器直接打开公开地址（例如 `https://10000-<id>.instabox.tech/xhttp`）：
   能打开（哪怕返回 404）说明网关是通的；
   打不开，说明用户本地到 instabox.tech 这条路有问题，
   先查 DNS 解析和 TLS 连通，不要急着换传输。
5. Clash 日志的报错行原样发出来，不要只说“用不了”。

## 2. 两个传输都延迟“-”或超时

- 先确认上面第 1 节的 1–4 项。
- 再看 Clash 日志：是 DNS 失败、TLS 失败、还是连接超时，
  三种报错的修法完全不一样。
- 换传输只能解决“某一传输不兼容”这一类问题，
  如果是网关地址本身在用户本地不通，XHTTP 和 WS 会一起失败。

## 3. 暂停后第一次连超时

正常现象，不是故障：

- 免费档 30 分钟无活动就暂停，公开端口请求会唤醒它，
  请求最多等 45 秒，Clash 的延迟测试可能等不到，
  多测两次。
- 单次连续运行 480 分钟到点后是冷却，5–20 分钟内任何唤醒、
  启动、exec 都会被拒绝，等冷却结束再试。
- 不要用保活脚本绕闲置暂停。

## 4. 助手自己沙箱里测不通

如果助手的沙箱出口代理会拦截 TLS（表现为
`tls: first record does not look like a TLS handshake`），
那是沙箱网络的问题，不是节点故障。
改用机器本机经公开地址的 `server/test.sh` 为准，
并在交付时把这一点说清楚，不要把沙箱失败写成节点失败。

## 5. 配置相关

- UUID 换了，客户端配置必须同步换；setup.sh 重跑不会换 UUID，
  但如果手动删了 `/data/xray/uuid.txt` 再跑，就会换。
- 机器里是明文端口，不要在机器里再套 TLS，TLS 由网关做。
- 公开端口 + 正确 UUID 才能用，错 UUID 必须失败；
  如果错 UUID 也能用，说明鉴权出问题了，立即停掉并检查配置。
- Clash 文件加了 DoH DNS，不要加 fallback，否则可能触发 GeoIP 下载，
  在某些环境会失败。

## 6. 什么时候该停下来问用户

- 服务端和机器本机实测都通过，但用户本地两个传输都不通，
  且浏览器也打不开公开地址：这是用户本地网络问题，
  服务端再改配置也解决不了，先让用户提供本地的解析、连通和日志结果。
- 用户要求公开分享节点、给多人用、绕过平台限制：
  拒绝这一部分，只保留个人使用的部分。
